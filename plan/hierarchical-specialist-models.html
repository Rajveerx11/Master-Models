03Agentic Requirement — Where Each Capability Actually Lives

Read/write/bash/MCP/skills are not model features — they are harness tools. The model's job is to drive them: emit correct tool-call JSON, loop over results, know when to stop. So base selection has one non-negotiable filter: native function calling + agentic training.
MCP + skills need zero special model support beyond solid tool calling — MCP tools arrive as ordinary tool schemas; skills arrive as prompt content.

06Dataset Factory — Custom Data, Generated with Fable 5

Standard 2026 recipe, proven numbers: small human seed → frontier teacher generates → judge filters hard → train. Fable 5 plays both teacher and judge. The judge filter is the single most important step — unfiltered synthetic data is worse than a smaller filtered set.
Every pair passes a machine judge AND a human spot check before entering training — this is where "entire control over what we give it" is enforced in practice.

Trajectory format is mandatory. Because every model must drive tools (section 03), training pairs are agentic trajectories, not plain Q/A: task → tool_call(read file) → result → tool_call(edit) → result → tool_call(bash test) → result → final answer. Fable generates these as full multi-turn conversations in the harness's tool-call format. Mix: ~60% domain trajectories · 15–20% general function-calling data (keeps tool JSON sharp) · 20–30% general instruction data — research shows adapter fine-tuning on narrow structured data measurably degrades tool planning, and 20–30% general mix is the documented mitigation.

Domain must be tight. "Frontend" is too broad — the only published small-beats-big wins are single-framework scale (a 14B tuned on one Rust framework beat a 32B by +21 points on that framework). Specialist #1's domain = your exact stack, e.g. "React + your design system + your conventions", not a whole discipline.

⚠️ One legal checkbox before generating at scale: provider terms restrict using frontier-model outputs to train competing models. A private internal specialist tool is a different situation than a commercial rival model — read Anthropic's current usage policy once before committing the pipeline to Fable outputs, and keep the option of an open-weight teacher (DeepSeek/Qwen-Max class) as licensing fallback.

07Honest Risks (updated for v2)

Fine-tuning erodes tool calling. Train on plain Q/A pairs and the specialist gets domain-smart but starts emitting malformed tool JSON or stops using tools — fleet becomes chat bots.
Fix: trajectory-format datasets (section 06 mix), tool-calling eval in every gate (valid-JSON rate, right-tool rate), train with the exact chat template the harness uses.
Catastrophic forgetting on hard specialization. Pure frontend-only data makes the model stylish but dumber at reasoning.
Fix: LoRA not full fine-tune, 20–30% general data mixed in (documented mitigation), before/after general-reasoning eval every train.
Orchestrator quality caps the whole system. Now that it also judges and merges specialist output (not just routes), its dataset is the hardest to build.
Fix: train it last, on real logged traffic from phases 1–2, not synthetic guesses. Include explicit "unsure → ask user / escalate" route class.
Self-graded eval gate. Same person writes seeds, teacher prompts, judge rubric, and eval — the specialist can "win" by matching the Fable data distribution, not by being better.
Fix: eval tasks pulled from real repo history (closed issues, actual diffs) BEFORE any dataset work starts; eval stays frozen and held out of all generation prompts; gate baseline = stock Qwen3-Coder-30B, not base Qwen3-8B; score task completion in the live harness, not answer similarity.
Specialists ≠ automatic wins; published data scale is against us. Real agentic distillation wins used 100–250K trajectories, and 7B still lost to 32B on SWE-bench. 2K pairs buys format + stack conventions, not deep capability.
Fix: tight domain per specialist, hard kill-gate per model, no fleet commitment — a losing domain keeps routing to the stock generalist.
Swap latency × agent loops. Real tasks are 20–100 serial model calls; interleaving specialists mid-task means 5–10 s load + KV re-prefill per hop — minutes of dead time. Multi-agent handoffs are also the documented failure zone (MAST audit: 79% of failures are coordination breakdowns).
Fix: route ONE specialist per whole task, never interleave mid-task; cross-domain tasks go to the stock generalist; all-resident fleet is a later hardware decision.
Teacher-output licensing. See section 05 checkbox.
Fix: read policy once; fallback open-weight teacher ready.

08Roadmap — Kill-Test First, Fleet Conditional

0
The 48-hour test (this weekend, $0, no training). Pull 20 real tasks from your own repo history (closed issues, actual diffs). Run stock Qwen3-Coder-30B-A3B in pi/Hermes on all 20; score task completion + tool-call validity. Freeze this eval set forever — it is written BEFORE any dataset exists and never appears in generation prompts.
Output: the baseline number every specialist must beat. If stock 30B already handles your daily work — project done, you won for $0.
1
Specialist #1 kill-test (2 weekends, hard cap $100). ONE tight domain — your exact stack ("React + your design system"), not "frontend". Factory run: 50–100 seeds → Fable trajectories → judge filter → spot check → ~2K pairs (60/20/25 mix) → QLoRA on Qwen3 8B.
GATE: beats stock Qwen3-Coder-30B on the frozen eval, in the live harness. Win → phase 2. Loss → STOP training; ship phase 0 setup + frontier escalation, keep harness + factory as assets.
2
Conditional — second specialist + simple routing. Repeat factory for next tight domain (backend stack or code review). Routing stays dumb and harness-level: one specialist per whole task, cross-domain → stock generalist, hard → frontier. Log every route + outcome.
